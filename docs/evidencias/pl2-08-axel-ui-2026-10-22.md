# PL2-08 — Sección E: contraste API ↔ web en navegador (matriz de Axel)

Fecha de ejecución: 2026-10-22.
Responsable: `@AxelHerrera11`.
Entorno: macOS (zsh), Node.js 24.14.1, Google Chrome 155.0.8059.85 controlado por Playwright 1.64.1 (instalado temporalmente fuera del repositorio, sin descargar navegadores), Firebase CLI 15.34.0. Emuladores Auth y Firestore Standard con el proyecto desechable `demo-pulsolink-axel-ui`, recreados en cada ejecución. Sin nube ni hardware.

## Preparación

- Revisión comprobada: `main` en `394b3a3` más los cambios de esta rama.
- Recorrido completo navegador → Vite → API Express → emuladores. Lo orquesta `tools/firebase/verify-patient-browser.cjs` (Gerson), que siembra datos ficticios, arranca API (13001) y web (15173) y crea las credenciales en memoria.
- Modo nuevo `PULSOLINK_UI_CONTRAST_ONLY=true`: después del login real del viewer, ejecuta `tools/qa/ui-contrast-acceptance.cjs` y termina, sin repetir el historial largo.
- El módulo crea por la API real, con la sesión admin del navegador, dos pacientes, una placa, una asignación y una sesión ficticios. No intercepta ni fabrica respuestas.

## Comandos ejecutados

```sh
npm ci && npm run build
FIREBASE_PROJECT_ID=demo-pulsolink-axel-ui PULSOLINK_PLAYWRIGHT_MODULE=<ruta temporal>/node_modules/playwright \
PULSOLINK_BROWSER_CHANNEL=chrome PULSOLINK_UI_CONTRAST_ONLY=true PULSOLINK_EVIDENCE_DIR=docs/evidencias/pl2-08-axel-ui/rN \
npx -y firebase-tools@15.34.0 emulators:exec --config firebase/emulators.test.json --project demo-pulsolink-axel-ui \
  --only firestore,auth 'node tools/firebase/verify-patient-browser.cjs'
```

En Windows/PowerShell, el orquestador usa Edge por defecto (`PULSOLINK_EDGE_PATH`) o `PULSOLINK_BROWSER_CHANNEL`. Las variables se definen con `$env:NOMBRE='valor'`.
