## 1. Objetivo de una noche

Demostrar este recorrido en una computadora: **iniciar sesión → seleccionar el dispositivo simulado → crear e iniciar una sesión → recibir mediciones por API → ver tres indicadores → finalizar → volver a consultar las lecturas guardadas en Firestore.**

Se limita la demostración a un dispositivo simulado y una sesión activa a la vez. Se prepara una cuenta operadora para presentar; otra cuenta sirve para comprobar aislamiento. No se requiere interfaz para administrar cuentas ni dispositivos.

Esta es una reducción explícita del alcance del primer avance respecto al README: gráficas, filtros de fechas, navegación avanzada del historial, despliegue público, automatización completa de CI y escenarios adicionales del simulador quedan para una siguiente iteración. No se cambian los contratos existentes ni se elimina funcionalidad ya terminada. Si un endpoint admite parámetros aún no implementados, documentarlos y rechazarlos expresamente; no ignorarlos silenciosamente.

**Conservar:** React/TypeScript/Vite, Node/Express/TypeScript y Firebase Auth + Cloud Firestore Standard. Web y simulador consumen la API. Credenciales administrativas solo en backend. Mantener módulos y repositorios sencillos; no introducir microservicios ni otra base de datos.

**Demostración funcional:** Firestore real para el recorrido integrado. Si el acceso a Firebase bloquea la noche, usar emuladores como contingencia y declarar expresamente que la integración con la nube está pendiente. No presentar datos estáticos del navegador como integración terminada.
